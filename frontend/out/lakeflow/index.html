Production Pipeline

Lakeflow Declarative Pipelines · Auto Loader · Quality Gates

The previous labs showed AI Functions interactively. This lab productionizes the same patterns using Lakeflow Declarative Pipelines — a declarative framework for incremental, self-healing, quality-gated data pipelines.

Industry: 🏦 Financial Services

Medallion architecture with AI Functions

Process new product documents and transactions continuously as they arrive, extracting merchant details and product terms.

Bronze

Raw file bytes + metadata ingested via Auto Loader (cloudFiles). Schema-on-read, append-only.

Silver — Parsed

ai_parse_document() applied to extract text. One row per source document.

Silver — Enriched

ai_query() + ai_classify() applied to parsed text. CONSTRAINT filters drop bad AI outputs.

Gold — Insights

Quality-gated, deduped, analytics-ready results. Joins, aggregations, and downstream consumption.

1

Review the pipeline notebook

The pipeline is defined in notebooks/05_lakeflow_pipeline.py. It uses @dlt.table decorators to declare each layer — no imperative scheduling code.

ℹ️

Key patterns in the pipeline notebook

  • Auto Loader: spark.readStream.format("cloudFiles") for incremental file ingestion
  • Streaming tables: Bronze and Silver layers process new files automatically
  • Quality constraints: @dlt.expect_or_drop() filters bad AI outputs before Gold
  • Batch Gold: Final layer is a regular (non-streaming) table for easy querying
notebooks/05_lakeflow_pipeline.py (excerpt)python
@dlt.table(
    name="bronze_documents",
    comment="Raw document bytes ingested via Auto Loader",
)
def bronze_documents():
    return (
        spark.readStream
        .format("cloudFiles")
        .option("cloudFiles.format", "binaryFile")
        .option("pathGlobFilter", "*.pdf")
        .load(volume_path)
        .select("path", "content", "length", "modificationTime", ...)
    )
notebooks/05_lakeflow_pipeline.py (excerpt)python
@dlt.table(name="silver_enriched")
@dlt.expect("has_failure_mode", "extracted.failure_mode IS NOT NULL")
@dlt.expect_or_drop("valid_downtime", "extracted.downtime_hours >= 0")
def silver_enriched_mfg():
    return dlt.read_stream("silver_parsed").selectExpr(
        "path", "filename", "parsed_at",
        """from_json(ai_query(
            'databricks-meta-llama-3-3-70b-instruct',
            CONCAT('Extract RCA from: ', parsed_text),
            responseFormat => '{"type":"json_schema","json_schema":{"name":"response","schema":{"type":"object","properties":{"failure_mode":{"type":"string"},"severity":{"type":"string"},"downtime_hours":{"type":"number"}}}}}'
        ), 'failure_mode STRING, severity STRING, downtime_hours DOUBLE') AS extracted""",
        "ai_classify(parsed_text, ARRAY('critical','major','minor')) AS severity_action",
    )

Create the Lakeflow pipeline

Create the pipeline via the Databricks UI, CLI, or via the DAB bundle. The pipeline configuration passes the industry as a Spark configuration variable.

Pipeline configuration (UI or API)json
{
  "name": "ai-functions-workshop-fins",
  "catalog": "main",
  "target": "ai_functions_workshop_fins",
  "configuration": {
    "pipeline.industry": "fins",
    "pipeline.schema_prefix": "ai_functions_workshop"
  },
  "libraries": [{ "notebook": { "path": "/path/to/notebooks/05_lakeflow_pipeline.py" } }],
  "serverless": true,
  "channel": "PREVIEW"
}
⚠️

PREVIEW channel required

ai_parse_document requires the "channel": "PREVIEW" setting in the pipeline configuration, as it is a preview-stage AI Function.

Run and monitor the pipeline

Trigger via CLI or DABbash
# Via Databricks CLI
databricks pipelines start --pipeline-id <pipeline_id>

# Via DAB bundle run
databricks bundle run -e dev setup_job --var industry=fins

# Check status
databricks pipelines get --pipeline-id <pipeline_id>
💡

What to watch in the UI

The pipeline graph shows each table layer with:
  • Record counts processed per run
  • Quality constraint pass/fail rates (look for CONSTRAINT violations)
  • Processing time per layer

Query the Gold layer results

Once the pipeline has run, the Gold table contains clean, structured, AI-enriched data ready for analytics and downstream ML.

Query Gold insights — Financial Servicessql
-- Explore the gold layer
SELECT
    filename,
    product_name,
    product_type,
    apr_low,
    apr_high,
    min_income_usd,
    processed_at
FROM main.ai_functions_workshop_fins.gold_insights
ORDER BY apr_low;

Schedule for production

Add a scheduled trigger in databricks.ymlyaml
resources:
  pipelines:
    fins_pipeline:
      name: "AI Functions Workshop - FINS"
      catalog: main
      target: ai_functions_workshop_fins
      serverless: true
      channel: PREVIEW
      configuration:
        pipeline.industry: fins
        pipeline.schema_prefix: ai_functions_workshop
      libraries:
        - notebook:
            path: ./notebooks/05_lakeflow_pipeline.py
      # Trigger daily at 6 AM UTC
      trigger:
        cron:
          quartz_cron_expression: "0 0 6 * * ?"
          timezone_id: "UTC"
