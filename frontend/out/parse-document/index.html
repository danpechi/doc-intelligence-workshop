Document Parsing

ai_parse_document

NEW

ai_parse_document bridges the gap between file-based data in Unity Catalog Volumes and SQL analytics. It natively extracts text from PDFs, images, and Office documents — enabling all other AI Functions to work on content that was previously locked in files.

Industry: 🏦 Financial Services | Documents: 5 Loan and credit card product specification sheets

The document intelligence pipeline

Volume (PDFs)→read_files(binaryFile)→ai_parse_document()→ai_query / ai_classify→Delta Table
1

Inspect documents in the volume

The setup job uploaded 5 synthetic Loan and credit card product specification sheets to your volume. Let's verify they are accessible.

List PDF files in the volumesql
SELECT
    path,
    REGEXP_EXTRACT(path, '[^/]+$', 0) AS filename,
    ROUND(length / 1024.0, 1)     AS size_kb,
    modificationTime
FROM read_files(
    '/Volumes/main/ai_functions_workshop_fins/documents',
    format => 'binaryFile',
    pathGlobFilter => '*.pdf'
)
ORDER BY modificationTime DESC;
✅

Expected: 5 rows

You should see 5 PDF files. If the volume is empty, return to the Setup tab and initialize the FINS dataset first.
2

Parse document text with ai_parse_document

ℹ️

What ai_parse_document accepts

  • PDFs — both text-based and scanned (OCR)
  • Images — PNG, JPEG, TIFF
  • Microsoft Office — Word (.docx), PowerPoint (.pptx)
ai_parse_document — extract text from PDFssql
SELECT
    REGEXP_EXTRACT(path, '[^/]+$', 0) AS filename,
    CAST(ai_parse_document(content) AS STRING) AS parsed_text  -- content is the binary column from read_files
FROM read_files(
    '/Volumes/main/ai_functions_workshop_fins/documents',
    format => 'binaryFile',
    pathGlobFilter => '*.pdf'
)
LIMIT 3;
3

Chain with ai_classify — bulk document categorization

Pass the parsed text directly to ai_classify in a single SQL expression. The entire PDF catalog is classified in one query.

Classify all FINS PDFssql
SELECT
    REGEXP_EXTRACT(path, '[^/]+$', 0) AS filename,
    ai_classify(
    CAST(ai_parse_document(content) AS STRING),
    ARRAY('secured_loan','unsecured_loan','premium_credit_card','standard_credit_card','secured_card')
) AS product_category
FROM read_files(
    '/Volumes/main/ai_functions_workshop_fins/documents',
    format => 'binaryFile',
    pathGlobFilter => '*.pdf'
);
4

Chain with ai_extract — pull structured fields

Extract entities from FINS PDFssql
SELECT
    REGEXP_EXTRACT(path, '[^/]+$', 0) AS filename,
    ai_extract(
    CAST(ai_parse_document(content) AS STRING),
    ARRAY('product_name','apr_range','min_income','max_amount')
) AS terms
FROM read_files(
    '/Volumes/main/ai_functions_workshop_fins/documents',
    format => 'binaryFile',
    pathGlobFilter => '*.pdf'
);
5

Full pipeline — parse → classify → extract → save to Delta

Combine all three functions in a single CREATE TABLE AS SELECT to process the entire document catalog and persist results in Delta Lake.

Full FINS document intelligence pipelinesql
CREATE OR REPLACE TABLE main.ai_functions_workshop_fins.parsed_product_sheets AS
SELECT
    REGEXP_EXTRACT(path, '[^/]+$', 0) AS filename,
    CAST(ai_parse_document(content) AS STRING) AS raw_text,
    ai_classify(CAST(ai_parse_document(content) AS STRING), ARRAY('secured_loan','unsecured_loan','credit_card')) AS product_type,
    from_json(ai_query(
        'databricks-meta-llama-3-3-70b-instruct',
        CONCAT('Extract product details: ', CAST(ai_parse_document(content) AS STRING)),
        responseFormat => '{"type":"json_schema","json_schema":{"name":"response","schema":{"type":"object","properties":{"product_name":{"type":"string"},"apr_low":{"type":"number"},"apr_high":{"type":"number"},"min_income_usd":{"type":"integer"}}}}}'
    ), 'product_name STRING, apr_low DOUBLE, apr_high DOUBLE, min_income_usd BIGINT') AS structured,
    current_timestamp() AS processed_at
FROM read_files('/Volumes/main/ai_functions_workshop_fins/documents/', format => 'binaryFile', pathGlobFilter => '*.pdf');
💡

Performance tip

ai_parse_document is called once per row and the result is reused by bothai_classify and ai_query in the same SELECT. Databricks optimizes this automatically via common subexpression elimination.
